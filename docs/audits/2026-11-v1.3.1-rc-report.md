# v1.3.1 release-candidate report — 2026-11-09

**Status: candidate built and verified. Not tagged, not published.** The steps
that would make it public are listed at the end and are waiting for a human
decision.

## What is in the candidate

Three correctness fixes plus the release documents that were missing:

1. DSH `session.v4.jsonl.zstd` discovery, with a warning for unrecognised
   session-shaped files.
2. UTF-8 stdout/stderr at both stdio entry points (`voyager`, `voyager-mcp`).
3. Literal-scan fallback for queries shorter than three characters, with
   `idx_events_ts`.
4. `docs/releases/v1.2.0.md` and `v1.3.0.md` (backfilled, and they say so).
5. `evidence verify --help` lists the five outcomes and exit codes, pinned by a
   test against `evidence.EXIT_CODES`.
6. README (both languages) states that `main` carries fixes that `@v1.3.0` does
   not include.

No new features. No breaking change. No removal.

## Release steps (not executed)

1. `git tag -a v1.3.1 -m "v1.3.1 — correctness patch"` on the merge commit.
2. `git push origin v1.3.1` — `release.yml` then builds, runs the full suite,
   `twine check`s, creates a **draft** Release, attaches both artifacts, and
   publishes only when every asset is present.
3. PyPI is **not** automated by that workflow; it stays a manual,
   credential-held step (and the `voyager` name on PyPI belongs to another
   project — see `docs/pypi-checklist.md`).
