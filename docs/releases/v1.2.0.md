# v1.2.0 — a read no longer writes

**Released 2026-10-19.** This note was backfilled on 2026-11-09 from the
`CHANGELOG` section for the same version; the GitHub release body was written at
release time.

Two themes. First, the surfaces stopped claiming things that were not true: a
bundle carries the exit status of the command it quotes, a handoff refuses to say
"nothing to switch" when there are two threads, and a read against a missing
index no longer creates one and answers "no matches". Second, continuity became
something you can look at before acting on it.

## Added

- **Evidence-aware continuation.** A tool result's exit code is joined to the
  command that produced it by call id, so a failed command cannot sit in a bundle
  looking like a successful one. An assistant claim is labelled as a claim, not a
  verified fact.
- **Multi-session repo scope.** With no WorkThread, the repo fallback compiles
  from the newest bounded set of sessions and reports `selection_scope`,
  `selection_reason`, `scope_ambiguous` and `excluded_session_count`, so a recency
  default is visible as a default.
- **Dashboard continuation preview.** One read-only `continue_context` per shown
  WorkThread: selected sessions, budget, bundle, and the exact command. No lease,
  no pending attach, no bundle written.
- **Dashboard session explorer.** Every session in scope opens to its whole
  conversation — tool calls with exit codes, origin, source state, owning
  WorkThread.
- **`thread_id` on `voyager_continue` / `voyager_context`** — the MCP surfaces
  could tell a caller to pick a thread but gave them no way to.
- **Browser-level verification.** A real-browser smoke test (Edge/Chromium,
  `--dump-dom`, no framework) covering filtering, navigation, the ambiguity
  statement, the preview and hostile-content escaping.

## Upgrade

From v1.1.0: no migration.
