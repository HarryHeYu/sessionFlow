# sessionFlow v1.0.0-rc1
**Unified AI Coding Agent Session Management**

Release candidate. Tag: `v1.0.0-rc1`.

## Features

- **Unified indexing across AI coding agents** — Codex, Claude Code, DSH
  (DeepSeek Harness), ZCode, Grok, Cursor, Kiro and Antigravity, normalized
  into one local SQLite index. Read-only against provider files.
- **Cross-agent full text search** — FTS5 (trigram) over every indexed
  session, with structured filters (provider, repo, time).
- **Timeline and provenance tracking** — one canonical WorkThread timeline:
  derived facts (attachments, handoffs, checkpoints, pending resolution)
  and persisted transitions (source missing/returned/archived, thread
  status), each event with provenance and deterministic ordering.
- **Session continuation and handoff** — `continue` / `switch` / `handoff`
  / `merge` compile a tiered context (authoritative L0 thread state +
  bounded L1 window + retrieval hint) for the next agent, with cross-agent
  lease coordination.
- **Retention and historical lifecycle management** — a vanished provider
  source retains the normalized history (searchable, exported, on the
  timeline) instead of deleting it; explicit archiving marks
  ARCHIVED_CANONICAL.
- **Doctor diagnostics and safe repair** — read-only diagnosis with an
  audited repair boundary: only derived-state repairs (FTS rebuild, stale
  cache) run under `--fix`, each transactional, idempotent, with a dry-run
  plan.
- **DSH bridge integration** — versioned JSON bridge (`schema_version` 1)
  consumed by the [dsh-sessionflow](https://github.com/HarryHeYu/dsh-sessionflow)
  plugin (six tools), plus an MCP server.

## Verification

- 970+ tests passing (full gate)
- bridge contract verified against the pinned core (O6.5 consumer gate)
- plugin compatibility verified (`npm test` / `npm run build` green)

**Live verification:**

- only providers with persisted evidence in this machine's
  `verification_events` table are reported LIVE/zero-touch; the doctor, the
  `verify` CLI and this README all cap claims at declared capability until
  evidence exists
- no unsupported live claims: providers without a startup surface (e.g.
  DSH) are reported NOT_FOUND for startup verification regardless of other
  capabilities
