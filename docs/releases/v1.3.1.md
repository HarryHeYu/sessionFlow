# v1.3.1 — correctness patch

**Release candidate. Not tagged, not published.**

No new features, no schema change, no breaking change. Three defects reported
against v1.3.0 are fixed, each with a regression test, plus the release documents
that were missing for v1.2.0 and v1.3.0.

## Fixes

**DSH 0.2.1-rc.3 renamed its transcript, and discovery never saw it.**
`session.jsonl.zstd` became `session.v4.jsonl.zstd`. The adapter globbed only the
old name, so every session written after the rename was invisible while `scan`
printed a clean total with no warning — the worst shape a data bug can take.
Discovery now accepts both names (`session.v*` covers later renames) and `scan`
warns when it finds session-shaped files that no known pattern claims. The parser
was already format-agnostic; only discovery was wrong.

**Windows wrote stdout in the ANSI code page while the DSH bridge decoded
UTF-8.** Every non-ASCII title arrived as U+FFFD; the index was fine and only the
transport was wrong. `voyager` and `voyager-mcp` now force UTF-8 on stdout/stderr
at the entry point (`util.force_utf8_stdio`), with no environment variable needed.
The SessionStart hooks keep their own copy on purpose: they are required to have
zero internal imports.

**Queries shorter than three characters returned nothing.** FTS5's trigram
tokenizer indexes 3-character windows, so `voyager search 补丁` — two CJK
characters, the common case — silently matched 0 rows. Short phrases now take a
literal `instr()` scan over the same `event_fts.body` the index stores, ordered by
`ts` (never `rowid`), backed by a new `idx_events_ts`. Measured on 469k events:
**2.2 ms** when the phrase occurs, **~0.44 s** when it does not — proving absence
requires the full scan — versus 0 rows before.

## Documentation

- `docs/releases/v1.2.0.md` and `v1.3.0.md` were missing although `release.yml`
  reads `v<version>.md`. Both are backfilled from `CHANGELOG` and say so.
- `voyager evidence verify --help` now lists the five outcomes and their exit
  codes, with a test comparing the text against `evidence.EXIT_CODES` so the two
  cannot drift (MAINTENANCE #12).
- README (both languages) states that `main` carries unreleased fixes and that
  installing `@v1.3.0` does not include them.

## Upgrade

From v1.3.0: no migration. The only schema change is an additive
`CREATE INDEX IF NOT EXISTS idx_events_ts ON events(ts DESC)`, applied on first
open. Rolling back is safe: v1.3.0 ignores the extra index.

## Verification

- Core suite: 1338 passed / 6 skipped before this patch; the new tests are in
  `tests/test_dsh.py`, `tests/test_utf8_stdio.py`, `tests/test_search_short_query.py`
  and `tests/test_evidence_help.py`.
- Short-query benchmark: 469k events, synthetic, Windows 11 / Python 3.13.12.
- Windows UTF-8: `PYTHONIOENCODING=gbk` end to end, bytes asserted, not strings.
