# Release v1.6.0 — product delivery

These are the release notes for the published **v1.6.0** tag, which carries
wheel and sdist assets. Install from the immutable tag shown under Upgrade.

## Added

- `voyager merge --repo <path>` names the repository of a **new** WorkThread.
  Reusing an existing thread never rewrites its repository; a conflicting value
  is reported as a warning.
- `voyager preview` is a read-only Handoff Preview. It compiles the same bundle
  `continue` would hand off, lists ambiguous WorkThread candidates, and takes
  no lease, writes no bundle and launches nothing.
- WorkBuddy desktop is an indexed read-only provider. Only file structure and
  JSON types were inspected; no real conversation text was read.
- The VS Code extension gained a read-only WorkThread Selector, selection
  correlation, source-missing indications and safer bridge lifecycle handling.
- DSH events now have a structural provenance classifier; unknown kinds remain
  `UNKNOWN`.
- Two reproducible continuity benchmarks are in the repository. They are
  research tools; no live model completion rate is claimed.

## Fixed

- New users no longer see stale install pins or a six-tool Quickstart: both
  READMEs and Quickstart describe the published Core v1.5.0 / Plugin v1.3.0
  pairing and all seven tools.
- A malformed stdio API request can no longer kill the long-lived bridge used
  by VS Code.
- Selecting one WorkThread in VS Code now switches to that exact thread.
- Source migration is reported as a read-only, explicitly suspected diagnosis;
  history is retained and never silently rebound.
- Several benchmark ground-truth and verdict-provenance defects were closed.

## Compatibility

- Bridge schema remains `1`; Store schema and continuation semantics are
  unchanged. `evidence_verify` remains an additive op from v1.5.0.
- Released pairing: Core 1.6.0 with Plugin 1.4.0. Plugin 1.4.0 still works
  with Core v1.5.0 when `repo` is omitted; an explicit `repo` against Core
  v1.5.0 fails with a clear `INCOMPATIBLE` message and no write.
- Core 1.6.0 reads indexes created by v1.4.1 / v1.5.0; v1.4.1 also reads a
  v1.5.0 index. No migration is required.

## Upgrade

Install from the immutable release tag:

```sh
python -m pip install "voyager[all] @ git+https://github.com/HarryHeYu/sessionFlow.git@v1.6.0"
```

There is no PyPI release. Rollback to `@v1.5.0` is supported and does not
change the index schema.

## Known limitations

- Real VS Code Extension Host / Webview E2E remains NOT VERIFIED without an
  authorized GUI environment (Core #59).
- Live Agent completion rates remain NOT VERIFIED; OS-level Runner isolation
  is BLOCKED.
- DSH provenance coverage and Native Resume are not claimed as fully verified.
- `Evidence MATCH` means reference consistency, not that a quoted claim is true.
