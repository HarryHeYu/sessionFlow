# v1.3.0 — a continuation reference you can check

**Released 2026-10-20.** This note was backfilled on 2026-11-09 from the
`CHANGELOG` section for the same version; the GitHub release body was written at
release time. Nothing here is a new claim about the tag.

The headline: a bundle used to say *which session* a claim came from and stop
there. It now names the event, and `voyager evidence verify` answers whether that
event is still the one it was recorded from.

## Added

- **`voyager evidence verify <session> <seq> [digest]`** — five separated
  outcomes with matching exit codes: `MATCH` (0), `MISMATCH` (1), `NOT_FOUND`
  (2), `UNVERIFIABLE` (3), `INVALID_REFERENCE` (4). `--json` emits a stable
  object. Read-only: no lease, no scan, no bundle, no migration.
- **Source-metadata check** — `mtime` and `size` were recorded per source and
  never read back; `verify` now stats the file and reports the comparison, hedged
  in both directions (equal metadata is not byte equality).
- **`voyager show` prints `#seq/digest`** on every event line, so a reference in
  a bundle resolves without comparing two windows by eye.
- **Handoff packages carry the reference** on the claim they hand over — the last
  step, and the one a user actually receives.
- **`tests/iso_guard.py`** — a fail-closed guard that refuses any path resolving
  into real agent data, including `..`, mixed separators, Windows casing
  differences and planted symlinks.

## Fixed

- **The fingerprint was not canonical.** A `|`-delimited join made
  `content="a|b", command="c"` and `content="a", command="b|c"` collide, so a
  changed event could read as unchanged. Serialisation is now canonical JSON and
  the algorithm is named (`sha256-8hex-json-v1`).
- `voyager continue --out` dropped the evidence reference from the claim it wrote.
- Three cross-platform defects in the isolation tests (hardcoded `\`, a
  Windows-only casing assertion, a hand-built subprocess environment without
  `SYSTEMROOT`).

## Verified, not claimed

- **v1.2.0 → main upgrade: 23/23.** The index was written by the released v1.2.0
  code extracted from the tag, then read by the current tree; no row and no schema
  object changed.
- **The evidence journey: 23/23.** Compile → locate with `show` → verify → rewrite
  the history → re-scan → the same reference reports `MISMATCH`.

## Upgrade

From v1.2.0 or v1.1.0: no migration. The index is read as-is. Rolling back is
safe because nothing was migrated.
