# Voyager v1.4.0

Feature release, **2026-11-13**. Adds one indexed agent and fixes the release
build. No schema change — the core bridge schema stays `1`, so this is fully
compatible with the DSH plugin **v1.2.0** (which requires schema `1`); no plugin
change is needed.

## What's new

**OpenCode is now an indexed agent**, read **read-only** from its SQLite
database (`mode=ro` plus `PRAGMA query_only`). Three shapes ship in the wild and
all three are supported, detected from the schema itself rather than from a
version string:

| Shape | How it is recognised |
|---|---|
| `v2` (v2.2.x) | `session_v2` + `session_message` + `session_part` |
| `v2-inline` (v2.0.x) | `session_v2` + `session_message`, and **no** `session_part`; content lives inline in `session_message.data` |
| `legacy` (pre-v2) | `session` / `message` / `part` |

The parts shape wins whenever `session_part` exists, so a v2.2.x database is
never mis-read as inline. Messages, tool calls, tool results and reasoning map
to the same event kinds every other adapter emits. Provider-generated rows
(`system`, `synthetic`, `compaction`) stay `meta` with
`origin=provider_system` and are never promoted to a human instruction. A tool
whose state is still `running` yields a call and **no** invented result. Events
are ordered by `seq` with a deterministic tiebreak, so a re-scan is idempotent.

An explicit `VOYAGER_OPENCODE_DB` (or `OPENCODE_DB`) is now **authoritative**: it
used to add a candidate while the default data directory was still probed, so
naming one database could still open another. The channel files
(`opencode-<channel>.db`) are enumerated only when no override is set.

## What's fixed

**The release workflow rejected its own sdist, so no tag could build.** The
distribution check asked `"scratch" in name.lower()`, which matches
`tests/test_scratch_hygiene.py` — a legitimate file the sdist is *supposed* to
carry. `v1.2.0`, `v1.3.0` and `v1.3.1` all failed at that step:

```
sdist carries scratch/private content: ['voyager-1.3.1/tests/test_scratch_hygiene.py']
```

Both branches now match `scratch` as a **path segment**
(`(?:^|/)scratch(?:/|$)`), so a real scratch directory is still refused while a
filename that merely contains the word is not. The regression test runs the
workflow's own leaked-name predicates rather than restating them, and a
file-level mutation back to the old form turns it red.

Also corrected, because they contradicted the code: the READMEs claimed no real
OpenCode install had been observed and named two shapes, and `MAINTENANCE`
listed eight indexed agents. Three documents (both READMEs and
`docs/QUICKSTART.md`) plus a `MAINTENANCE` known-issue entry claimed
`voyager evidence verify --help` does not list the five outcomes — it does, with
their exit codes and the `MATCH` caveat.

## Tests

- Directed: **36** OpenCode tests (27 for the existing shapes + 9 for the inline
  shape), on anonymised fixtures carrying no user text, path or digest.
- Full suite: **1392 passed, 36 skipped** (Windows, Python 3.13, all extras).
  The 36 skips are optional-dependency and platform rows, each with a stated
  reason; none is an OpenCode test.
- One real install was observed (v2.0.29, byte-for-byte isolated copy):
  `probe` → `ok/v2-inline`, 8/8 sessions indexed, per-kind event counts
  identical to an independent read-only `sqlite3` oracle (user 68, text 206,
  reasoning 2053, tool call 2617, tool result 2617), and the real
  `.db` / `-wal` / `-shm` hashes plus all 20 table row counts unchanged.
  Record: [`docs/audits/2026-11-opencode-v20x-real-gate.md`](../audits/2026-11-opencode-v20x-real-gate.md).

## Verified, not claimed

- The real-install gate covers **one install, one version (v2.0.29), one
  platform (Windows)**. `session_discovery` and `session_indexing` stay
  `UNIT_VERIFIED`; nothing is promoted to `LIVE_VERIFIED` on that evidence.
- **Native resume is `NOT_FOUND`** — the adapter exposes no resume command, and
  none was observed. **Cross-agent continuation is `NOT_VERIFIED`.** Neither is
  claimed because discovery worked.
- **The Evidence `verify` API op is not in this release.** The Core side is
  still an unmerged pull request, so `evidence verify` remains CLI-only and
  `integration_info().ops` lists no `evidence_verify` op. DSH plugin **v1.2.0**
  keeps its six tools — no seventh tool is shipped or claimed.
- The README architecture illustration still shows the eight pre-OpenCode
  platforms; regenerating it is tracked separately (P3-b), and the surrounding
  prose is left consistent with the image rather than contradicting it.

## Upgrade

No migration. The bridge schema stays `1` and no row, column or index changes,
so your index is read as-is and rolling back to 1.3.1 is safe.

Install or upgrade, pinned to this tag:

```bash
pipx install "voyager[all] @ git+https://github.com/HarryHeYu/sessionFlow.git@v1.4.0"
```

> **Voyager is not published to PyPI** — the `voyager` name there is an
> unrelated library, so installation is from the tagged source above.
> `voyager upgrade` does not exist; re-run the command with a newer tag.

## Compatibility

- Core bridge schema: **1** (unchanged).
- DSH plugin: **v1.2.0** (requires schema 1) — compatible, no upgrade needed.
- Python >= 3.10; Windows / Linux in CI, macOS supported by the code but not in
  CI.
- Agents indexed: Codex, Claude Code, DSH, Grok CLI, ZCode, Kiro, Cursor,
  Antigravity, OpenCode.
